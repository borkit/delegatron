How it works

Four roles, one loop, clear rules.

Ask one AI model to write code and it will tell you the code works. Delegatron splits the job the way a small team would, so nothing reaches you unchecked.

  1. 01

    Plan

    An architect turns your request into small tasks, each with acceptance criteria and the tests that prove it.

  2. 02

    Build

    An implementer writes the code and its tests as a patch. Nothing touches your project until the patch is checked.

  3. 03

    Test

    The patch runs in an isolated sandbox. Failing tests are the one opinion nobody gets to argue with.

  4. 04

    Review

    A reviewer reads the change and the evidence, then approves it or sends it back with the problems in hand.

Features

Careful by design.

  • Any model, any role

    Local models on one 12 GB graphics card, cloud models, or a mix. Choose per role.

  • Hard limits, always on

    Iterations, spend and time are capped by Delegatron itself, not left to the model.

  • Evidence settles arguments

    Failing tests beat security checks, which beat reviewer objections, which beat opinions. Repeated disputes get one binding ruling.

  • Checks on every patch

    Leaked secrets, new dependencies and imports that won't resolve are caught before a patch is accepted.

  • Proof it stayed local

    Each run records every network destination it touched, so you can show that nothing left the building.

  • Thirty templates

    Web APIs, command-line tools, audits and test suites, with the details filled in when you start.

  • Six languages

    Python, JavaScript and TypeScript, Go, Rust, Java and PHP, each tested in its own sandbox.

  • Terminal, API or dashboard

    The same loop from a command line, a web API with live updates, or the dashboard. Every run gets its own branch.
